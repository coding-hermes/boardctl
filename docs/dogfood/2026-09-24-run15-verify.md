# boardctl dogfood run 15 — verify-the-fixes pass (2026-09-24)

## Angle

Runs 1-14 covered install, CLI core, report/serve/import, fleet multi-board, and
the workspace-burndown saga. v0.1.8 shipped with three user-facing fixes from the
last run (DF-BOARDCTL-8 burndown per-day labels, DF-BOARDCTL-9 read
tolerance/repair, BT-048) and 33 commits have landed on main since the tag. This
run's angle: **re-verify the promised workflow end-to-end with the released
v0.1.8 binary on a fresh machine, then exercise the two subcommands that landed
after the last dogfood (`sweep-status`, `install`) — the surfaces no run has

## Promise statement

*"A user can grab a checksummed static binary from GitHub releases with no
toolchain, and manage a coding-hermes JSONL board — create/update/event/validate
with byte-stable diffs and a 0/1/2 exit contract — then normalize off-vocabulary
statuses fleet-wide (sweep-status) and protect the board with a pre-commit lint
hook (install)."*
